# Governance Broker Guidelines

This skill provides the required patterns when modifying or interacting with the `harness.shared.governance.broker` module in the MangoMAS ecosystem. The broker is responsible for providing isolated execution boundaries, wrapping tool execution in timeout caps, and emitting constrained signals.

## ProcessBackend Abstraction

The broker uses a strictly defined `ProcessBackend` abstraction to invoke tools.

- **Rule**: Never bypass the `ProcessBackend` when invoking arbitrary shell commands or untrusted code on behalf of the agent.
- **Rule**: The broker runs at Layer 2 of the dependency DAG. It must NOT import anything from `agent_authority` or higher-level orchestrator modules, as this introduces cyclic dependencies.

## Timeout Caps & Execution Constraints

All process executions must be bound by a defined maximum runtime and maximum output bytes to prevent resource exhaustion and hanging processes.

1. **Timeout Cap (`DEFAULT_TIMEOUT_SEC`)**: Use `DEFAULT_TIMEOUT_SEC` to bound execution times unless the specific policy override requests otherwise.
2. **Output Bytes (`DEFAULT_MAX_OUTPUT_BYTES`)**: Output from standard error and standard output must be strictly truncated at `DEFAULT_MAX_OUTPUT_BYTES` to protect the JSON parser downstream.

## Immutable Signal Constraints

All results generated by the broker are packaged into an `ExecutionResult` dataclass. Ensure that this dataclass is fully immutable, json-serializable, and handles potential edge cases (like non-utf8 outputs gracefully escaping).

Use this skill whenever working on tool execution environments, isolation sandboxes, or modifying the `broker.py` subsystem.
