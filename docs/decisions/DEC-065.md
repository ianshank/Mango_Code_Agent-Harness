# DEC-065: Graph engineering lands as four derived checks; the traceability gate is re-scoped behind a ratchet

## Context

A three-model synthesis recommended adopting graph engineering across this repository, ranked
LangGraph static topology verification first. Peer review against the checkout
(`docs/reports/2026-DEEP-PEER-REVIEW-GRAPH-ENGINEERING.md`) accepted the diagnosis and rejected
the ranking, then reviewed itself and found five defects in its own plan. Spec:
`docs/specs/graph-engineering-adoption.md`, revision 3, whose design decisions are argued
Thesis → Counter-Argument → Rebuttal with the rebuttal required to introduce a third position.

Four defects were evidenced and are closed here. A fifth — the citation backlog the first exposes
— is bounded rather than closed, and that boundary is the substance of this entry.

**The traceability gate read a corpus it was not aimed at.** `check_traceability.py` resolved
`.governance/traceability.json` and every glob against the process CWD, and `make validate` ran
it from `harness/node`. It read **6** requirement IDs while `docs/specs/` held **412** sharing
not one member with them, and printed `traceability: passed (6 requirements)` with exit 0. Its
own docstring anticipated the failure — "the common failure where a glob is scoped to one stack
and silently checks nothing outside it" — and it shipped scoped to one stack. Its two emptiness
guards both passed: the failure mode is not "found nothing", it is "found the wrong two files",
which no emptiness check can catch.

**One approval flag was guarded by construction and by nothing else.** `policy_decision.decide`
takes `human_approved`, the single argument that turns a high-risk denial into an ALLOW.
`broker.py` sources it from a `context` mapping with an identity check (`is True`), and
`tool_executors.execute_run_command` builds that context as a literal dict with no such key, so
the agent path cannot reach it. The guarantee is real and rests on one dict literal;
`broker.execute_command(command, **kwargs)` makes forwarding a caller-supplied context
syntactically easy and no test would have gone red.

**Generated code was parsed and the parse discarded.** `execute_generate_code` runs `ast.parse`
to answer "does it parse", then writes. `synthesis.prohibited_imports` declares five entries the
same tree can decide before bytes reach disk. Those five span three shapes — importable modules
(`subprocess`, `importlib`), attribute call targets reachable through a bare `import os`
(`os.system`, `shutil.rmtree`), and a builtin no import statement names (`__import__`) — so a
checker built on `ast.Import` / `ast.ImportFrom`, the obvious reading of the key's name, decides
two of five and silently passes the other three.

**Two graph nodes were registered with no edges, and the suite asserted it.** `peer_reviewer` and
`security_reviewer` have no incoming or outgoing edge, so `findings` is empty on every run.
DEC-052 records this in prose; `test_langgraph_graph.py` asserts the node *set*, which both
orphans satisfy — so a fix wiring them in would not fail the test and a fix deleting them would.
The defect was pinned in place rather than caught.

## Decision

**Four checks land, none of them a new CI gate.** `validate_invariants.py` already carries four
invariants behind one `make validate` entry and `test_constant_triage.py` enforces a
repository-wide property from inside the ordinary pytest run with no target of its own. The
choice is which enforcement surface, not gate-or-nothing: a pure function over repository state
belongs in the test suite, where INV-2's zero-skip discipline already governs it. So
`ci_required_targets` is unchanged at ten entries, `harness/CONTRACT.md` gains no row, and INV-5
sees no new entry to reconcile. Only checks that must run outside pytest earn a target, and none
of these does.

**The traceability gate is re-scoped behind a ratchet, not flipped.** `check_traceability.py`
gains `--workspace`, defaulting to the current working directory so every per-stack shim
invocation behaves exactly as before and `harness/node/.governance/traceability.json` is not
touched at all — leaving it untouched is what proves the compatibility claim. A new root
`.governance/traceability.json` declares `"scope": "repository"`, and only a repository-scoped
run is subject to two new policy-sourced bounds: `min_discovered_requirement_ids`, an
anti-vacuity floor that makes "the gate is pointed at the wrong corpus" fail instead of pass, and
`max_uncited_contract_requirement_ids`, a ratchet that may be lowered as citations land and never
raised.

The enforced value is **223**, and its composition is stated because the number is the whole
control: **222** is the corpus as it stood before this change, and the **+1** is `R-GEA-5`, this
spec's own requirement that a tokens-per-turn baseline be recorded before any code-property graph
is built. That requirement is deliberately unimplemented, so it has nothing to cite, and citing it
somewhere convenient to reach 222 is exactly the failure this gate exists to catch. Every other
requirement the spec declares is cited on both sides. Where 222 appears below it means the
pre-change corpus, never the enforced ratchet.

**The ratchet is the honest half of this entry.** Re-scoping the gate does not produce a green
gate; it produces a backlog of **223** contract-spec requirement IDs missing an implementation
citation, a test citation, or both. Shipping the scope fix alone would have turned a gate that
lies into a gate that cries wolf, and the second gets switched off. Shipping it with the backlog
silently exempted would be the waiver `CLAUDE.md` forbids. The ratchet is neither: the number is
in policy, visible, asserted, and can only go down. Reducing it is a deliberate policy edit with
citations attached.

**The ratchet is enforced against an independent baseline, not against itself.** Review on
PR #120 found that `max_uncited_contract_requirement_ids` was a configurable ceiling rather than
a ratchet: the gate and every test exercising it read the same policy key, so raising the key from
223 to 224 alongside a new uncited requirement stayed green, and "may only be lowered" was prose
nothing checked. `ACCEPTED_RATCHET_CEILING` in
`harness.shared.tests.test_traceability_scope` records the highest value ever accepted, as a
deliberate second copy of the number; the configured policy value must be less than or equal to
it. Lowering the policy is a one-file edit that passes freely. Raising it above the baseline
fails, and raising the baseline is a visible edit to an accepted decision's high-water mark rather
than a threshold tweak. A companion assertion fails when the baseline drifts *above* the
configured value, because a ceiling with slack constrains nothing and is the stale-waiver shape
C-GEA-4 is about.

**Requirement IDs are classified per document, defaulting strict.** A document declares
`Spec class: program-plan` when its IDs name scheduled work with nothing yet to cite; five
roadmap documents carry that declaration. A document declaring nothing is graded as
`default_spec_class` — contract, the strict branch — and a document declaring an unrecognised
class raises rather than falling into the permissive branch. The permissive class is never the
default, because a class inferred from a filename is a class an author can acquire by accident.

**The authorization graph is derived and never stored.** A persisted copy of governance state is
a cache, and a cache of governance state is a staleness bug with a security consequence: the
stored graph says one thing while the broker enforces another. `authority_graph.py` recomputes
from the same functions the broker calls, holds no artifact, and is forbidden by test from being
imported by `harness/shared/governance/`, `write_policy.py`, `read_policy.py`, or
`agent_authority.py` — the graph reads the governance layer and the governance layer must not
depend on the graph.

**It models two grant surfaces and refuses to guess between them.** Each active role has a
tool-exposure surface (`allowed_actions`) and an execution-identity surface (the grant of
`EXECUTION_IDENTITY[role]`), and they deliberately disagree: `planner` holds `spec_write` while
executing as `orchestrator`, which lacks it; `verifier` holds `review_write` and `security_scan`
while executing as `test-eval`, which lacks both. A query that does not name a surface raises,
because a default would silently answer the wrong question with full confidence.

**What the high-risk reachability check is, and is not.** Of the five `high_risk_actions`, three
— `destructive`, `permission_change`, `secret_access` — are declared by no canonical role at all,
because they are `command_actions.classify` output rather than grants; `decide()` denies them by
absence, which is `default_deny` operationalised. `high_risk_actions` mixes a grant vocabulary and
a classification vocabulary in one namespace, which is what made this easy to miss. So the
reachability property is non-trivial for `external_write` and `production_change` only, and the
test says so in its own assertion messages rather than passing on three actions with no edge to
traverse. The neighbouring property is *not* a gap: `validate_agent_policy.py` already fails
closed on any role granting a high-risk action without approval-gating it. The plan's first
revision claimed a gap that was mostly closed, and the correction is recorded rather than
quietly applied.

**Every new check fails closed on an empty input set.** A derived node set, edge set, tool set,
requirement-ID set, prohibited-symbol list, or scanned call-site set that comes back empty raises
rather than reporting a satisfied property. This repository has been bitten by that exact shape
three times — DEC-024's carried-forward claim, DEC-052's assertion over a channel's whole domain,
and the traceability gate above — and an empty input is the cheapest way to make every downstream
property vacuously true.

**Topology verification ships as a test, not a gate, while DEC-053 stands.** The park is decided
but unexecuted: `harness/shared/langgraph/` is still at its original path and Phase E is blocked
behind NS-2, a credential rotation requiring a human at a provider. Forbidding the gate and the
plain test alike would leave the orphan-reviewer defect live and unwatched for that indefinite
period. So `graph_topology.py` extracts the topology from module **source** via `ast`, never from
a compiled graph object — which also means no `skipif` on an optional import, and therefore no
skip in search of an INV-2 waiver — and a test pins the two reviewers as edgeless *and* pins that
DEC-052 records them so, failing both when they are wired in without amending DEC-052 and when
either is deleted silently. A second test pins the absence of a topology CI *target* to DEC-053's
`accepted` status, and does not fail merely because a topology test exists.

**Accepted and stated rather than hidden.** `execute_generate_code` now denies one previously
accepted input class — Python reaching a `synthesis.prohibited_imports` symbol — where it
previously wrote the file. `write_file`, `apply_patch`, `read_file`, and `run_command` are
unchanged, preserving C-CGT-2. `governance-policy.json` gained a `traceability` block, so
`policy-artifact.json` and the control-plane bundle were regenerated and re-verified; the
`policy_version` moves accordingly.

## Consequences

**Gained.** Four properties that were argued in prose or held by construction are now asserted by
tests that go red when reverted: no agent-controlled input reaches `decide()`'s `human_approved`;
`verifier` reaches neither `external_write` nor `production_change`; generated Python reaching a
prohibited symbol writes zero bytes; the two orphan reviewers match what DEC-052 records. The
traceability gate reads the corpus it names, cannot silently shrink back to a stack, and carries
a backlog number that can only decrease.

**Paid.** Five protected paths change and require the `infra-reviewed` attestation:
`harness/shared/governance-policy.json` (the `traceability` block),
`harness/shared/governance/check_traceability.py` (workspace, classes, floor, ratchet),
`harness/shared/tool_executors.py` (the write-door wiring, kept to a few lines by putting the
analysis in the unprotected `code_safety.py`), `harness/control-plane/policy-artifact.json` and
the control-plane bundle (regenerated for the policy digest), and the new root
`.governance/traceability.json`. `harness/node/.governance/traceability.json` is deliberately
untouched.

**Risk accepted.** The ratchet at 223 is a bound, not a fix; a reader could mistake a passing
repository-scoped run for a fully traced corpus. The failure message and the policy rationale
both say the number is a backlog that may only be lowered, and `max_uncited_contract_requirement_ids`
sits in policy where lowering it is a reviewed edit rather than a code change.

**What the approval-flag property actually claims, stated precisely.** The check scans the
callers of `ExecutionBroker.execute_command` and reports any site whose broker `context` is not a
literal mapping — five non-test call sites today (`tool_executors.py`, three in
`verification.py`, one in `experimental/autonomous_healing.py`), zero witnesses across all 114
first-party modules. It is deliberately **not** scoped to `broker.py`'s own plumbing, where the
`context` parameter is passed on to `_policy_decision` by design; reporting that would fire on
correct code every run, and a check that fires on correct code gets switched off. So the property
is "no *caller* can supply `human_approved`", not "the flag is unreachable by any path". If the
external broker contract ever accepts a context from an untrusted transport, that is a different
hole and this check does not cover it. The distinction is recorded because a security property
whose scope is left implicit is one a later reader will over-trust.

`execute_run_command` is the one site whose safety needed real analysis rather than
pattern-matching: it passes its context inside a `**kwargs` dict built two lines earlier and
mutated by `kwargs["timeout"] = timeout`. A scan that flagged every `**` — the obvious
implementation — would have failed on correct code. The resolver follows single-binding names and
literal-key subscript assignment, and taints anything else (rebinding, `update`, `setdefault`,
`|=`, computed keys), with a test pinning that this real shape is not reported.

**Residual, named rather than discovered later.** `execute_generate_code`'s prohibited-symbol
check runs on the tree `_validate_code_syntax` produces, which exists only when
`validate_syntax=True` and the language resolves to Python. `validate_syntax` is a
model-supplied tool argument, so a caller that sets it false skips both the syntax check and
this one. Closing it means parsing unconditionally, which contradicts R-GEA-3's own wording
("reusing the AST already parsed") and widens a protected-path diff, so it is not closed here.
It is a real bypass and is recorded as one: the check raises the floor for the default path
without claiming to be a containment boundary. `write_denial_reason`, `authorize_write` and
workspace confinement all still apply on that path and are unaffected by the flag.

Relatedly, AC-GEA-5's literal wording — `execute_generate_code` raising under a *temporary*
policy declaring an empty `prohibited_imports` — is proven at unit level rather than end to end.
Pointing the executor at a temporary policy requires `MANGO_WRITE_POLICY_PATH`, and
`write_policy.write_denial_reason` then demands a pin-digest record for any supplied policy, so
the end-to-end form needs a pin fixture that does not exist yet. The raise itself propagates out
of `execute_generate_code` unchanged, which is the property the criterion is about.

**Not closed here.** The 223-ID backlog is bounded, not reconciled. The code-property graph
(R-GEA-5) remains gated on a tokens-per-turn baseline this repository has never measured, and is
deliberately not built on the strength of an imported benchmark. Learned topology optimisation
stays parked under DEC-027 with `synthesis.lats_enabled` false. The LangGraph park (DEC-053)
stays unexecuted and blocked behind NS-2; this entry adds a test that watches the defect in the
meantime, and no gate that would have to be removed when the park lands.
