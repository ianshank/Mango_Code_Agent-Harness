# DEC-048: The 2026 standards audit's gate-runner and test-hygiene slice

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

2026 standards audit, gate-runner and test-hygiene slice (§2, H8, M12, M15, M16, and three Low items). Two gates failed for reasons that were themselves findings: `make secrets` failed closed right after a successful `make secrets-install`, because `go install` writes to `$(go env GOPATH)/bin` and the recipe never looked there (CI passed only by prefixing PATH by hand); and `.claude/hooks/session-start.sh` installed `requirements-dev.txt` unhashed with system pip and, when that aborted, said nothing. All three Makefiles now resolve each Go-installed tool through PATH and then GOPATH/bin, leaving a name found in neither unchanged so the `command -v` guards still fail closed; the workflow PATH prefixes are removed so CI runs the gate exactly as a developer does. The hook installs the hashed lock with `--require-hashes` and then `-e . --no-deps` -- the CI recipe verbatim -- and names the step that failed on stderr, exiting non-zero. The root Makefile gains the `.SHELLFLAGS := -eu -o pipefail -c` both stack Makefiles already set. M12: `--allow-unix-socket` joins `--disable-socket` in addopts, and the 35 `enable_socket` marks whose real need was a unix socketpair (asyncio's self-pipe, anyio's BlockingPortal under TestClient -- never the 'loopback' the comments claimed) are removed; the three survivors (the egress-floor proof and the two live suites) each name their TCP need. `test_egress_floor.py` proves both halves in one test: a socketpair is created and, in the same guard state, AF_INET still raises. H8: pytest-randomly (5.0.0 on >=3.10, 3.16.0 on 3.9) and pytest-xdist 3.8.0 are pinned; `make test-python` and `make coverage-python` run `-p randomly -n auto`, the seed printed in the header. Enabling xdist on the coverage run was measured, not assumed: pytest-cov combined the workers' data (lines 99.22%/branches 97.81% against 99.24%/97.87% serial, same verdict) and both a collection-time and a runtime skip reached the evidence file under `-n 2`; wall time fell from 92s to 36s on four cores. The evidence writer now runs on the controller only. `os.chdir` in `test_validators.py` became `monkeypatch.chdir` and the module-level `TestClient` in the api_server suite became a fixture. Three seeded full runs (1, 2, 3) are recorded in the PR. M15: pip-audit 2.9.0 is pinned in requirements-dev.txt so it lands in the hashed lock; `make audit-install-python` installs the lock with `--require-hashes`, `PIP_AUDIT_VERSION` is read back from the pin rather than restated, and the drift workflow's `uv` install comes from the lock too. M16: every job in both workflows carries `timeout-minutes` (30 for the build legs, 20 for scan/audit, 15 for the weekly jobs -- ceilings ten times the observed durations), and the PR workflow cancels superseded runs per ref; the scheduled workflow deliberately does not, since a cancelled run there is a lost notification. Pinned by test_makefile_contracts.py (with a fake `go` driving the real Makefile), test_workflow_runtime_limits.py (split from test_workflow_contracts.py at the size budget, DEC-035's seam), test_agent_surface_liveness.py (a fake `python` driving the real hook), test_session_hooks.py and test_egress_floor.py, each with a negative case
