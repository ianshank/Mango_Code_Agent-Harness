# DEC-044: `main`'s ruleset drops the human-approval rules and keeps the nine required checks

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

R-CQ-1 / NS-1: `main`'s ruleset takes the second of the three recorded shapes -- `required_approving_review_count: 0`, the nine required status checks unchanged, `bypass_actors` still empty -- and `require_code_owner_review` drops with the count. The committed export had been unappliable since it was written, for a reason no one wrote down: `.github/CODEOWNERS` routes `*` to `@ianshank`, who authors every pull request in this repository, and GitHub does not accept an author's approval of their own pull request. One required code-owner approval plus one code owner who is always the author is not a strict review policy, it is a policy that can never be satisfied, so the export sat uncommitted to the live repository for four releases while every gate stayed advisory -- the branches API still reported `"protected": false` for `main` on 2026-09-04, which is how PR #79 and PR #80 both merged with zero approvals and how PR #60 merged with every check on its head red (DEC-024). The other two shapes were rejected on their own terms: a bypass actor for the repository-admin role is scoped to the *ruleset*, not to the review rule, so it would exempt its holder from the nine status checks as well -- reopening exactly the #60 hole in order to close a review hole; and a second reviewing account requires an account that does not exist and blocks every merge until it acts. Zeroing the count is the only shape that keeps the machine gates enforcing and removes only the human-approval rule the repository cannot honour; the review layer this gives up was already fictional, and the compensating control is the `openspec-peer-review` and `repo-invariant-review` skills plus the third-party PR review that found five real defects across PR #79 and PR #80. `test_nobody_can_bypass` no longer asserts an empty `bypass_actors` list -- an assertion the two rejected shapes could also satisfy -- but grades the export through `unchosen_shape_reason`, which is also run against `tmp_path` copies reshaped into each rejected shape, so the grader cannot pass by being merely well-formed. Five mutation proofs: reverting the export's count, reverting its code-owner flag, and gutting each of the grader's three clauses in turn each fail their tests. NS-1 is not closed by this entry: importing the export at Settings -> Rules -> Rulesets is a repository-settings action no CI job and no agent in this repository can perform, and the branches API is the only evidence that counts (DEC-024) -- this entry decides the shape and removes the reason it could not be applied, and NS-1 stays open until `"protected": true`
