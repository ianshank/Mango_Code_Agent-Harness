# DEC-047: The lock pins artefacts, not just versions, and `audit-python` scans the lock alone

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

R-CQ-10: `requirements-lock.txt` carries artefact hashes, every workflow install passes `--require-hashes`, and `make audit-python` now scans the lock alone rather than the lock plus two range files. The lock pinned versions and nothing pinned artefacts: a version number is a name a registry resolves, so a file replaced under an existing pin installed with no diff here and no warning there, while `test_workflow_contracts.py` asserted CI installed "from the lock" and was satisfied. All four `uv pip compile` recipes (`lock`, `lock-check`, `lock-upgrade-check`, `lock-upgrade`) pass `--generate-hashes`; regenerating changed 0 pins and added 2,249 hash lines across 79 distributions, verified by diffing the pin lines of the old and new files. The plan said two workflow install steps; there are three -- two in `python-package.yml` and one in `scheduled-drift.yml` -- and all three carry the flag, because a hashed lock read by an install that does not check it is decoration. The audit change is forced and was measured, not assumed: pip enters `--require-hashes` mode as soon as *any* input file carries a hash and then demands `==` on every requirement in every file, so `pip-audit --requirement requirements.txt --requirement requirements-langgraph.txt --requirement requirements-lock.txt` failed outright with `In --require-hashes mode, all requirements must have their versions pinned with ==. These do not: fastapi<1.0,>=0.110`, while `pip-audit --requirement requirements-lock.txt` returned `No known vulnerabilities found`. Scanning the lock alone is broader than the invocation it replaces, not narrower: `requirements-dev.txt` opens with `-r requirements.txt` and the lock compiles from dev + langgraph, so all 15 distributions named across the three inputs are pinned in the lock, which carries 79 -- the other 64 are transitive dependencies the range files never mention and the old form scanned only as a by-product of resolution. The ranges were also the wrong thing to scan: a range resolves to whatever the index offers that day, so the old invocation audited versions no leg installs. `test_dependency_lock_contracts.py` makes the subsumption a gate rather than a comment, and `test_workflow_contracts.py` splits at 653/700 along the seam DEC-035 names -- workflow *shape* there, dependency *set* here -- with `_workflow_paths.py` holding the constants both read instead of a second copy. Five mutation proofs: stripping one requirement's hashes, removing `--generate-hashes` from the header, dropping `--require-hashes` from one install step, restoring a range file to the audit target, and breaking the range-file parser's `-r` skip each fail their tests
