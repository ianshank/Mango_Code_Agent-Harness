# DEC-066: gaps.json stub corruption (MEM-1) remediation

## Context

AQA-004 (`test_gaps_memory_integrity.py::test_gaps_json_has_no_stub_entries`)
discovered that 199 of 223 entries in `.mango/memory/gaps.json` are stub
placeholders with `question="q"`, `what_needed="w"`, `proposed_approach="p"`.
These were produced by a sequence of failed `knowledge_gap_log` calls that passed
sentinel values instead of real content.

The stub entries corrupt the planner prompt via `format_gaps_for_planner()` and
bloat context with noise (DEC-058). They predate the write-denial protection
added in DEC-059.

## Decision

Prune all 199 stub entries from `.mango/memory/gaps.json`, preserving the 24
substantive entries. This is a human-attested data-cleanup operation on a
previously unprotected file. Post DEC-059 write-denial, future reasoner runs
cannot introduce stubs via the `write_file` tool path.

## Consequences

- The 24 substantive knowledge gap entries remain queryable by the planner.
- `format_gaps_for_planner()` output is reduced from 223 entries to 24.
- AQA-004 regression test passes and pins this invariant going forward.
- The stub entries are not recoverable; they contained no real information.
