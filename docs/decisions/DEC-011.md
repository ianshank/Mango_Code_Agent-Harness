# DEC-011: `run_command` routes through `ExecutionBroker`, so INV-8 is enforced on the live path

## Context

The MAS orchestrator routes run_command through ExecutionBroker, making INV-8 true on the live path for the first time: generated code now executes through the approved broker, which derives the action, obtains a policy verdict, runs the command guard, and pins cwd, timeout and captured output size. Active roles execute as the narrowest canonical contract that covers their work (reasoner as implementer, verifier as test-eval) rather than being added to agent-policy.json, which would be the agent's own governing policy gaining an execution grant; test_execution_identity_is_no_wider_than_the_role pins that the chosen identity is never wider than the role's derived authority. Accepted

## Decision

## Consequences

an active role the mapping does not declare cannot execute at all, and commands classified as external_write or destructive -- notably `pip install` -- are denied for the reasoner, so the reasoner prompt no longer instructs installing packages and directs the agent to knowledge_gap_log instead. test_invariant_liveness.py ships with an empty waiver dict; it was deliberately not landed alongside a waiver for INV-8, because a self-destructing waiver introduced in the same commit as its own fix can never fire
