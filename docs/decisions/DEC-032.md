# DEC-032: Post-implementation review found four gates that could report PASS on absent or wrong evidence, all 

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

Post-implementation review of the tech-debt hardening branch found four gates that could report PASS on absent or wrong evidence — the exact failure class DEC-024 was written about — plus one reproducible order-dependent test. All are fixed in the same change. (1) The Python zero-skip evidence hook read only `pytest_runtest_logreport`, so a module-level `pytest.importorskip` — which pytest reports as a `CollectReport`, never a `TestReport` — left no row and `make verify-zero-skips-python` printed `passed` while an entire module, sometimes a whole directory via its conftest, had vanished. Four live sites skip this way, including `test_egress_floor.py`, whose silent disappearance would remove the proof that the egress floor is armed. This is DEC-030's failure shape one layer up: there the hooks saw one of three suites, here one of two report types. Added `_skip_events.collect_skip_event` and a `pytest_collectreport` hook, with a `pytester` reproduction. (2) `coverage_gate._waiving_extra` matched with a raw `str.startswith`, so a policy prefix written without its trailing slash (`harness/shared/langgraph`) waived every sibling whose name merely began the same way (`langgraph_helpers.py`, `langgraphX.py`); the only policy check asserts the prefix names a real directory, which the slashless form does. Now matched on whole path segments. (3) `check_per_file` reported `[PASS] … 0 file(s)` when the waiver set covered everything — one policy edit (`path_prefixes: ["harness/"]`) disabled per-file enforcement entirely while the gate still said PASS. Now fails closed on zero measured files, consistent with the module's own "absence of evidence is never a pass" contract. (4) `test_constant_triage.check_row`'s decision-linkage check evaluated `Path("harness.shared.retry_policy").name.split(".")[0]` — `"harness"`, a substring of essentially every log line — and with `or`/`and` precedence only the symbol was ever really checked, so a constant could cite a decision about a different or nonexistent module and stay green; R-TDH-16/AC-16's entire enforcement rested on that expression. Replaced with a shape-aware `_module_names` and negative tests. `TEST_SIZE_BUDGET_LINES`, the one constant this branch itself introduced without a triage row, is now pinned to `limits.test_size_budget_lines`. (5) `json_logging.configure_gate_logging(__name__)` under `runpy.run_path(..., run_name="__main__")` permanently reconfigured the process-global `__main__` logger; fourteen modules across the three suites run scripts that way, and `test_nemotron_bridge.py::test_running_the_bridge_as_a_script_dispatches_main` failed whenever `test_pretooluse_guard.py` collected first. The full suite was green only because alphabetical order happened to be favourable — reverse file order was red. An autouse fixture in the repository-root conftest restores the logger; production behaviour is untouched. Also fixed: `_session_hooks` indexed the extras dict unguarded at module scope, so an adopter fork trimming `coverage.optional_extras` got a bare `KeyError` during conftest import with no diagnostic; and `deselect_langgraph` — the whole R-TDH-4 mechanism — had no test at all and was invisible to the coverage gate because `harness/shared/tests/*` is omitted from measurement. Correcting the record: DEC-027 states the parked modules are "byte-identical after the move". `lats_optimizer.py` is; `autonomous_healing.py` is not — it carries the `BROKER_SUCCESS` substitution from the Phase 2 verdict-constants work, which touched it before the move. The move was still content-preserving in intent; the word "byte-identical" was wrong and is corrected here rather than by editing an existing entry
