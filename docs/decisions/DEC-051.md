# DEC-051: The verification grader is imported from the toolchain, not the workspace, and the digested set is t

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

The verification grader is imported from the toolchain, not the workspace, and the digested set is the write door's set (Copilot review on PR #86, extending DEC-049). Two more forgery routes were found against the digest check and both were reproduced before being closed. (1) `python -m pytest` puts the current directory first on `sys.path`, so a `pytest.py` -- or a `pytest/` package with an `__init__.py` -- written into the workspace with a permitted `write_file` was the pytest the recipe ran; it exited 0, the failing suite graded VERIFIED, and no digested file had changed. `PYTEST` in the root Makefile is now `$(PYTHON) -I -m pytest` and the Makefile exports `PYTHONSAFEPATH := 1` to every recipe so the xdist workers, which execnet starts with `python -u -c` and which therefore begin with the current directory on their path whatever the parent's flags, are guarded on Python 3.11 and later. Test modules still import `harness` through pytest's own `pythonpath = ["."]`, applied after pytest and its plugins have loaded. The regression proves both recipe shapes on a real failing suite and `test_makefile_contracts.py` pins the real one. (2) The digest walk pruned `validate_invariants.SKIP_DIR_PARTS`, a CI-gate convenience, while the write door prunes nothing: `*.pth` reaches into `.venv/lib/*/site-packages`, exactly where the interpreter loads startup files from, so a `.pth` could change there under both digest checks. The walk now skips only `write_policy.ALWAYS_DENIED_SEGMENTS` (`.git`), measured at about 0.5 s over this repository with `node_modules` present against 0.2 s pruned -- a directory walk, since only matching files are hashed. `**/sitecustomize.py` and `**/usercustomize.py` join `protected_paths` (the root-only forms left the nested ones writable through the direct door; both declared dormant, armed before use). (3) `make` long options are recognised by exact spelling or not at all: GNU getopt_long resolves any unique prefix, so `--dir=` reached make as `--directory=` and `--ev=` as `--eval=` while the classifier compared full spellings; an option outside a documented allowlist of harmless full spellings is refused, `-e`/`--environment-overrides` is refused as `NAME=value` by another route, and a harmless option never consumes the token after it so `--jobs PYTEST=evil` is still caught. (4) Tool outcomes are typed, not parsed: the executors return `tool_result_format.ToolText`, a `str` carrying the outcome the executor decided (`denied_policy`, `failed`, `invalid_arguments`), and both the dispatcher's `tool_call` event and the MCP transport's log read that attribute; the dispatcher had logged a refused write as `executed` because the handler returned, and the MCP prefix table had logged a successful read of a file beginning with `Error:` as a denial. Three residuals stated in SECURITY.md and accepted until OS isolation: swap-and-restore inside the run, workers on Python < 3.11, and the toolchain's own packages living in the workspace virtualenv. The verdict remains a statement that the harness's own gate commands ran unmodified and exited 0; it is not a statement about what the agent's tests assert
