# DEC-054: `harness/jvm/` is relocated to `docs/adopters/jvm-template/` (Memo 2 option B / R-SR-26 / NS-31)

## Context

JVM stack relocated out of the live harness (NS-31 / R-SR-5 / R-SR-26; Memo 2 option B; audit H14).

`harness/jvm/` is an unadopted reference that violates the repo's first non-negotiable and is never built -- coverage floors are literals in `build.gradle.kts`, no committed wrapper/lock/verification metadata (templates only), ~4 lines of product Kotlin (`PolicyAnchor.kt`), file-content tests only, and zero root-workflow references (H14; NEXT_STEPS NS-31). It still costs 14 shim scripts, 8 personas, a `.governance/` mirror, and every test/`digest-regen` path that loops `("node", "jvm")`

Options considered: (A) promote to a real stack -- commit wrapper + lock + verification metadata and add CI -- rejected: no adopter, no product surface beyond the template, and hard-coded floors contradict policy-sourced floors elsewhere; (B) relocate to `docs/adopters/jvm-template/` and delete live harness coupling -- chosen (Memo 2 option B; R-SR-26); (C) delete outright -- rejected: the template remains useful adopter documentation once it is not pretending to be a third live stack

R-SR-5 / AC-5 (this entry + GOVERNANCE_SKILL); R-SR-26 / AC-26 (`ls harness/jvm` fails; `docs/adopters/jvm-template/build.gradle.kts` exists; `make digest-regen` with no jvm profile; no `("node", "jvm")` loop). Evidence: plan review-record "Four in-or-out memos"; audit H14

## Decision

move the template under `docs/adopters/jvm-template/` (keeping `build.gradle.kts` and the documented adopter layout); delete its per-stack shims, personas, and `.governance/`; make bundle tooling tolerate an absent `jvm` profile; retarget every test that loops `("node", "jvm")` to node-only / workspace-parameterised form (AC-26). Migration: Phase E step 12, two PRs per Memo 2, first among the four Phase E deletions (order SoT: jvm → langgraph → openspec → mirroring). Does not change Node or Python runtime behaviour
