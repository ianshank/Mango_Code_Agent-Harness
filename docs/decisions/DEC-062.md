# DEC-062: Windows portability: asyncio/Starlette self-pipe requires enable_socket under pytest-socket

## Context

`test_mcp_server.py`, `test_api_server_regression.py`, and `test_main.py` use
`asyncio.run()` / Starlette `TestClient` / AnyIO portals. On Linux the asyncio
self-pipe is an AF_UNIX socketpair, which `--allow-unix-socket` in addopts
already permits. On Windows Python builds without native AF_UNIX, Python's
asyncio self-pipe falls back to a loopback TCP socketpair, which
`pytest-socket` then blocks.

Originally logged as DEC-059 on the feature branch; renumbered to DEC-062 on
merge so the AF_UNIX egress-floor skip could keep a distinct ID (now DEC-063,
after `origin/main` published DEC-059 for NS-37/NS-38).

## Decision

Add a `sys.platform == 'win32'` conditional
`pytestmark = pytest.mark.enable_socket` at module level in the affected test
files. This does not affect Linux CI where AF_UNIX is always available and the
TCP floor remains enforced.

## Consequences

On Windows, the TCP egress floor is temporarily lifted for the MCP server and
API server test files so the suite can exercise the servers. Production paths
remain unchanged; Linux CI continues to enforce the TCP floor fully.
