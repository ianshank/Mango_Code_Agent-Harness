# DEC-042: The containment layer grades the words the shell produces, not the command text

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

The containment layer grades the words the shell produces, denies credential files on the way in as well as out, and asks one authority question from both transports. Five defects, each reproduced by running the real modules before it was fixed, all present on `main` at `487870a`. (1) `command_actions.classify` scanned the raw command text with `(?:^|[\s/])` boundaries while `process_backend` runs every command through `bash -c`, which strips quotes, resolves backslashes, expands braces and expands globs first -- so `cat .en?`, `head .e*`, `cat '.env'`, `cat \.env` and `cat {.env,README.md}` each graded `read`, the action *every* role holds including the verifier, while opening the file. The check now runs over `shlex.split` output with bounded brace expansion, which closes quoting and escaping at the seam rather than by adding three more patterns to a regex; a glob must *commit* to a credential name (its literal prefix begins one, or its literal suffix ends one) so `ls src/*` stays an ordinary read, and dotglob is honoured so `*.py` and `*rc` are untouched. (2) `_COMPOUND` listed `$(` and backticks but not `<(`, so process substitution ran a second command under a `read` grade. (3) `write_denial_reason` had no credential rule: `protected_paths` names control-surface files and `.env` is deliberately untracked, so it matched nothing and returned `None` -- and `resolve_environment` reads `NVIDIA_BASE_URL` from the repository-root `.env`, which is the API server's workspace, so one `apply_patch` redirected the next `complete_chat` to a host of the model's choosing with the real bearer token attached. The alternation moves to `write_policy` (the edge `read_policy` already imports across) and both doors compose it; `read_policy` re-exports, pinned by object identity. **This corrects DEC-012**, which states credential denial is the read side's and that `apply_patch` reuses `write_denial_reason` unchanged: denial is now bilateral, and (4) `execute_apply_patch` consults `read_denial_reason` *first*, because its `matched 0 times` / `matched 1 times` reply was a substring oracle over every file `read_file` refuses. Corrected by a new entry rather than by editing DEC-012, per DEC-032. (5) `mcp_server` asked the policy decision point whether the acting role holds `write`; `ToolDispatcher`, the path the orchestrator actually runs, asked nothing -- so the planner and the verifier were refused by one transport and admitted by the other. `authorize_write` now lives in `tool_executors` and both call it, asking the policy decision point for the `write` action directly through the new public `ExecutionBroker.authorize_action(agent_id, action)` so one action model grades both doors. The action is given, not derived: the first form of this fix synthesised `tee <path>` and let `classify` grade it, and a `filepath` of `-find` made that answer `read` -- the action every role holds -- so both doors admitted the writes the fix existed to refuse. **Accepted behaviour change**: the planner and verifier can no longer write or patch in-process. They hold no `write` action in `agent-policy.json` and were already refused on the MCP transport; the loop now honours what the model always declared. Seven runtime-enforcement modules join `protected_paths` (`tool_executors.py`, `orchestrator/**`, `nemotron_bridge.py`, `tool_schemas.py`, `agent_prompts.py`, `tool_dispatch.py`, root `conftest.py`) -- a third group beside the enforcement layer and the agent control surface, because the verifier's verdict is a `make test-python` run that imports that `conftest.py`. `command_actions.py` reached 510 lines against a 500 budget and splits along the seam the defects drew: `shell_words.py` owns what a word can *reach*, the classifier owns what a command *does* (DEC-035's rule). `HookRunner` resolves `orchestrator.tool_timeout_sec` instead of storing `None` and handing it to `subprocess.run`, where it means no timeout at all; `policy_decision.decide` takes `human_approved` keyword-only. Every gate carries a mutation proof, and the procedure that produced them is now `.mango/skills/gate-mutation-proof/SKILL.md` (NS-20), written after running it by hand against every gate this change added or altered. No total is claimed: an earlier draft said "ten" and the PR body said "twelve", and neither was reconstructible, because the same gate was mutated again after its tests were strengthened. Which mutation ran against which gate and what it produced is recorded; a count nobody can check is the claim DEC-024 refuses
