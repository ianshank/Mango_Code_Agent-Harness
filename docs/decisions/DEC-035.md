# DEC-035: `coverage_gate.py` (470/500 lines) splits into threshold enforcement and `coverage_scope.py` (which 

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

`coverage_gate.py` splits along the seam its own defects drew, and two defects in the gate-truthfulness batch's own gates are fixed. The gate reached 470 lines against a 500-line `limits.size_budget_lines` -- one edit of headroom -- so the measurement-*scope* concern moves to `harness/shared/coverage_scope.py` (per-file floor, optional-extra waivers, source discovery, measured-set bound) while `coverage_gate.py` keeps the aggregate-*threshold* concern (load_thresholds, measure, check, per_file_enabled, main). The seam is not a line count: every defect ever found in this area has been a scope defect rather than a threshold one -- the `startswith` waiver prefix that covered siblings, the waiver set that covered everything and still printed `[PASS] 0 file(s)` (both DEC-032), and the `omit` entry that dropped a file from the floor while raising the aggregate (R-GT-3). Backwards compatible by construction: `coverage_gate` re-exports every moved symbol including the two private helpers existing tests reach (`_importable`, `_waiving_extra`), the standalone `python harness/shared/coverage_gate.py` path keeps its ImportError fallback, and both modules measure 100%. The split invalidated three test-side assumptions that no assertion would have caught, each fixed: `test_the_gates_own_directory_cannot_shadow_the_extra` patched `coverage_gate.__file__` while `_importable` now reads `coverage_scope.__file__`, so the DEC-032 regression had stopped exercising anything (production behaviour is identical -- both modules sit in `harness/shared/`, so "the script's own directory" resolves to the same path); and sixteen `caplog.at_level(..., logger=cg.logger.name)` sites stopped seeing records emitted under the new module's name, now anchored on the `harness.shared` parent so a future move cannot blind them again. Separately, two defects in the batch's own new gates, found by probing them rather than by any test: `declared_source_roots`'s table regex required a following `[`, so a `pyproject.toml` whose last table is `[tool.coverage.run]` matched nothing and the gate failed closed reporting "declares no table" -- accurate about the regex, false about the file, and unrunnable for an adopter fork shaped that way; and `check_secret_allowlist.declared_keeps` scanned the whole config, so a `# keep:` comment anywhere in `.gitleaks.toml` -- a header comment, prose after the block, a commented-out rule -- exempted an entry from the liveness check, which is the same "a control an unreviewed edit elsewhere can widen" shape the batch exists to close. Keeps are now scoped to the `[allowlist]` block. Both carry regression tests that fail against the pre-fix code
