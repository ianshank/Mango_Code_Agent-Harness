# DEC-055: The `openspec/` tree is folded into `docs/specs/` and deleted (Memo 3 option Y / R-SR-28 / NS-31)

## Context

`openspec/` folded into `docs/specs/` and the strict tier deleted (NS-31 / R-SR-5 / R-SR-28; Memo 3 option Y; audit M22).

`openspec/changes/*` is a second, orphaned spec system -- three proposals (`add-egress-floor`, `add-neurosym-governed-synthesis`, `fix-protected-path-portability`) live outside `docs/specs/`; the `openspec` CLI is in no requirements file or workflow; `REQUIRE_STRICT_SPEC_VALIDATOR` defaults to 0 so the strict tier in `harness/shared/validate_specs.sh` has never run fail-closed (M22). Structural + plan tiers already gate every PR via `make specs`

Options considered: (X) install and pin the `openspec` CLI and require the strict tier -- rejected: doubles the spec SoT, adds an unpinned binary to the hashed lock surface, and the proposals are ordinary markdown the structural tier can already check once folded; (Y) fold the three proposals into `docs/specs/*.md` and delete the tier/tree -- chosen (Memo 3 option Y; R-SR-28); (Z) leave as-is -- rejected: NS-31 / C-CQ-2 block Phase E while a closed-plan constraint still told agents to keep `openspec/`

R-SR-5 / AC-5; R-SR-28 / AC-28 (`ls openspec` fails; `make specs` gains three documents; no `REQUIRE_STRICT_SPEC_VALIDATOR`; no `specs` partial-coverage entry). Evidence: plan review-record "Four in-or-out memos"; audit M22

## Decision

convert the three `openspec/changes/*` proposals into `docs/specs/*.md` documents that pass `make specs`; delete the strict tier, `REQUIRE_STRICT_SPEC_VALIDATOR`, its tests, and the `openspec/` tree (AC-28). The `.mango/skills/openspec-peer-review` skill name stays -- it is peer-review procedure, not the CLI tree. Migration: Phase E step 14, two PRs per Memo 3, after jvm relocate and langgraph park
