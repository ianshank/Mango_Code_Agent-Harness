# DEC-007: `protected_paths` is enforced at tool-call time by the write gate, not only by CI

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

protected_paths becomes a runtime write gate as well as a CI review gate: _execute_write_file consults validate_invariants.is_protected at tool-call granularity, reusing the CI matcher rather than a second implementation, and denies the git directory explicitly because git never lists it and protected_paths structurally cannot cover it. Enforcement was not absent before, it was at agent-turn granularity via the pre-nemotron-run hook, which leaves a whole tool-call budget unchecked and never re-validates the last agent's own writes. tool_broker_reference.py (the PDP the broker executes as a host subprocess before the guard runs), write_policy.py and mango_mas_orchestrator.py join protected_paths and CRITICAL_PATTERNS: the enforcement points were themselves unprotected
