# DEC-025: Constant triage: every operational constant the audit found unlinked is now a policy value (`process

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

Constant triage (tech-debt-hardening-plan R-TDH-16; inventory and gate in `test_constant_triage.py`): every operational constant the audit found unlinked is now either a policy value or accepted here, and a third state is a test failure. Moved into policy: `process_backend.DEFAULT_MAX_OUTPUT_BYTES` becomes `orchestrator.max_output_bytes` (65536) read through `policy_loader.orchestrator_defaults()` -- a captured-output ceiling is a containment control, the same reasoning that moved `DEFAULT_TIMEOUT_SEC` earlier. Equality-pinned rather than re-sourced: `retry_policy.DEFAULT_MAX_RETRIES` must equal `nemotron.max_retries` (the module is stdlib-only by design and takes its overrides from the resolved mapping the bridge passes in). Accepted as true constants: `retry_policy.DEFAULT_BASE_SEC`, `DEFAULT_MAX_SEC` and `DEFAULT_JITTER_RATIO` (the bridge's backoff shape, overridable per call through the NEMOTRON_* mapping; a governance threshold would be `max_retries`, which is already policy); `shadow_planner.DEFAULT_SHADOW_TIMEOUT_SEC` (an operator env knob, `MANGO_SHADOW_TIMEOUT_SEC`, documented in .env.example and capped at the orchestrator API timeout, so it can never exceed a policy value); `cognitive_signal.MAX_SIGNAL_BYTES` and `MAX_SINK_BYTES` (protocol ceilings of the observation channel fixed by docs/specs/mangomas-integration-core.md R-MMI-3; changing them is a spec change, not a tuning). Accepted with a recorded divergence: the Node client's resilience defaults -- `harness/node/src/ai/nemotron/circuit-breaker.ts` (`failureThreshold` 5, `resetTimeoutMs` 10000, `halfOpenSuccessThreshold` 2) and `harness/node/src/ai/nemotron/nemotron-client.ts` (`baseBackoffMs` 500, `maxBackoffMs` 5000) -- are constructor-overridable client-local defaults with no Python counterpart of the same shape (Python backs off in seconds with proportional jitter), so there is nothing for them to drift from; a shared `resilience` policy block would be the way to unify them and is left as an open question rather than invented here. The policy-sourced Nemotron request values (`timeout_ms`, `max_retries`, `temperature`, `max_tokens`) are handled separately by R-TDH-13
