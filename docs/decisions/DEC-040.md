# DEC-040: The attestation check reads the PR description from the API, not `github.event.pull_request.body`, a

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

The attestation check reads the pull request description from the API, not from `github.event.pull_request.body`, and `edited` joins the workflow's trigger types. Correcting DEC-038, which specified the payload field: that field is a snapshot taken when the run was queued, and the mechanism failed on its second real run in three separate ways. (1) Staleness: the description was corrected minutes after the push that queued the run, so the check judged text that no longer existed and reported a missing row for `.mango/skills/protected-path-attestation/SKILL.md` against a table that already had one. (2) Unclearability, which is the serious one: `edited` was not a trigger type and "Re-run failed jobs" replays the *original* event payload, so a stale description could never be cleared -- the only way past the gate would have been an otherwise pointless commit, and a gate whose only escape is a no-op commit trains people to make no-op commits. (3) Disclosure: passing the description through an environment variable printed the entire body into the step-setup group of the CI log, which is noise at best and, for a description that ever carried something sensitive, a leak into logs retained beyond the PR. The step now fetches `/repos/{owner}/{repo}/pulls/{number}` with the job token, writes `.body` to a file with a one-line Python reader, and passes only the path; the description still never reaches the shell as code. `set -euo pipefail` is explicit because the runner's default `bash -e` does not set pipefail, and a failed fetch would otherwise leave an empty file that the gate reports as a missing table -- a true failure for a false reason, which is the diagnosis-obscuring shape DEC-032 objected to. `pull-requests: read` is declared on `build-full` alone rather than workflow-wide, so the matrix and audit jobs keep `contents: read` and nothing more; a test asserts that scoping, and a second asserts the payload field does not return. `edited` fires on title edits too, which is the accepted cost of a description fix being able to re-run the check that judges it. Also recorded: the first version of the `edited` assertion searched the trigger section for the string and passed on the comment explaining why `edited` is there, so deleting the type left it green -- found by mutating the workflow rather than by reading the test, and now asserted against the parsed `types:` list
