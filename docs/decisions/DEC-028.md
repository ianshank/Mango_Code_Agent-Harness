# DEC-028: The Python 3.9 floor stays

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

The Python 3.9 floor (`requires-python >=3.9`) stays for now, and two consequences of keeping it in the CI matrix are handled explicitly instead of by red CI or an ignore flag. (1) Per-file coverage on the 3.9 leg. langgraph declares Requires-Python >=3.10, so that leg deselects the `langgraph`-marked suites (tech-debt-hardening-plan R-TDH-4) and `harness/shared/langgraph/{decorators,graph,nodes}.py` measure at 20-40% lines there, failing `coverage.per_file` while every other leg holds them at floor; the number was measuring the interpreter, not the code. `governance-policy.json -> coverage.optional_extras` now declares each optional extra with `import_name`, `deselect_env` and `path_prefixes`. `coverage_gate.py` waives the per-file lines floor for files under those prefixes only when that env is `1` AND `importlib.util.find_spec(import_name)` is None (the same predicate conftest.py uses to deselect), logs every waived file at WARNING with its measured value, keeps the aggregate `coverage.lines`/`coverage.branches` floors and every other file enforced, and fails closed on a malformed block. `conftest.py` reads the deselect variable's name from the same policy key through `policy_loader.coverage_optional_extras()`, so the deselect signal and the waiver have one source; `test_coverage_gate.py` pins the liveness (shipped policy names the extra, env and directory conftest and the workflow use). This is a structured, visible waiver, recorded here because INV-style gates do not get quiet exceptions. (2) pytest. PYSEC-2026-1845 is fixed in pytest 9.0.3, which requires Python >=3.10. requirements-dev.txt pins `pytest==9.0.3; python_version >= "3.10"` and `pytest==8.4.2; python_version < "3.10"`; the universal lock carries both with markers. The dependency-audit (3.9) job already runs continue-on-error (pre-existing, not introduced here), so the retained 8.4.2 pin shows there as a reported finding rather than being suppressed with `--ignore-vuln`. uv moves to 0.11.15 for its four advisories on every leg. Both waivers end the day the floor moves to 3.10, which is a product decision that needs its own spec (the JVM/Node adopters and the `check-compat` gate are the readers of that floor)
