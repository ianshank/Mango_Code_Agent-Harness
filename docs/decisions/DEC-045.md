# DEC-045: Every `uses:` in `.github/workflows/` is a 40-hex commit SHA with the version comment Dependabot wri

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

R-CQ-9: all 20 `uses:` references in `.github/workflows/` are pinned to a full 40-hex commit SHA with the version comment Dependabot writes, and the references are pinned at the majors already in use rather than at the majors the open Dependabot pull requests propose. A tag is a moving reference: `@v5` is whatever the owner last pointed `v5` at, so an upstream account compromise reaches this repository's runners with no commit here for the diff review or the secret scan to see -- and `harness/CONTRACT.md` has required SHA pinning of adopters since before this repository did it itself. The version comment is load-bearing, not decoration: `NODE24_ACTION_MAJORS` is enforced against the major the comment states, so a bare SHA would silently drop a reference out of the Node 24 check. Every SHA was resolved with `git ls-remote --tags` against the action's own repository, taking the peeled `^{}` value for annotated tags (`pnpm/action-setup` v5.0.0 is one: its tag object is `b307475…` and its commit is `fc06bc12…`; pinning the tag object would resolve to nothing). Staying on the current majors is the deliberate half: R-CQ-9 is a pinning change, and `actions/checkout` v7, `actions/setup-python` v7, `actions/setup-node` v7, `actions/setup-go` v7 and `pnpm/action-setup` v6 are all available -- taking them would fold five untested major bumps into a supply-chain change whose whole point is that what CI runs stops moving. Dependabot #62-#66 propose exactly those bumps and are superseded in mechanism, not in substance: once the reference is a SHA, Dependabot updates the SHA and its comment, and a tag-bump pull request no longer applies as written; whether to take the major bumps is a separate call with its own PR. `uses_lines` now parses only the strict form and `unpinned_uses` reports everything it rejects, with a test asserting every `uses:` line is either graded or reported so an unpinned action cannot pass the Node 24 table by being invisible to it; a `./`-relative composite action is exempt, having no SHA to pin. Six mutation proofs, one of which the fix failed first: the short-SHA case carried no version comment, so the pattern rejected it for the missing comment and loosening `{40}` to `+` left the test passing -- a case that cannot fail for the reason it names pins nothing. It now carries a valid comment, joined by an over-long and an upper-case case, so the quantifier and the character class are each pinned from both sides. Correction after review: the `./` composite-action exemption was stated twice -- `unpinned_uses` skipped local actions while the test reconciling the graded and reported sets counted them -- so the reconciliation would have failed the first time either workflow grew a local action, and passed until then because neither has one. The exemption now lives only in `pinnable_uses`, which both read. The first proof of that fix was itself incomplete and the mutation run said so: reverting the reconciliation to a raw count still passed, because it ran against the two real workflows alone and neither can distinguish the two counts; it is now parametrised over a third case that has a local action, and the revert fails on it. Second correction after review: two of the three form cases stated reasons that are simply untrue. `git rev-parse` resolves an abbreviated object id and resolves an upper-case one -- both checked against a real git, both the opposite of what the case said ("a branch name as far as GitHub is concerned", "which git does not resolve"). The cases are right and the rule is right; the reasons were invented. The rule being enforced is this repository's, not git's -- one canonical 40-hex lowercase form, because an abbreviation stays unambiguous only until the upstream repository grows a colliding prefix, and because `git ls-remote` and Dependabot both emit lowercase so one spelling keeps pins comparable by eye and Dependabot's rewrite a one-line diff. A failure message that states a false reason is worse than one that states none: it misleads exactly the person who hit the gate
