# DEC-029: DEC-020 stands: `harness/shared/` is not regrouped (cyclic on the real import graph

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

Two structure decisions from tech-debt-hardening-plan Phase 4, recorded so the next audit does not re-derive them. (1) DEC-020 stands (R-TDH-20): `harness/shared/` is not regrouped into `core/`/`tooling/`/`runtime/`. The plan's revision-1 proposal was withdrawn under peer review because the split is cyclic on the real import graph (`policy_loader` <-> gate scripts <-> `governance/`), and because `protected_paths`, `check_dedup.py`'s shim classification and the 20 per-stack delegating scripts all name the flat paths. New gate-like modules land under `harness/shared/gates/` when one is needed; any move requires a superseding `DEC-` entry and an import-acyclicity test landed first. (2) The `sys.path` bootstraps stay as they are (R-TDH-21, AC-21's accepting-entry branch). `git grep -c "sys.path.insert" -- harness/shared harness/node/scripts harness/jvm/scripts` reports 31 sites in four styles: the shared entrypoints' `try: import harness.shared... except ImportError: sys.path.insert(0, <repo root>)` (the DEC-019 shape), the unconditional `parents[2]` in `validate_plan.py`/`validate_specs.py` (inside the same `except ImportError`), the ten per-stack `runpy` delegators, and the ten per-stack walk-up imports. Deduplicating them into a helper is impossible by construction: the bootstrap exists because `harness.shared` is not yet importable when a script runs as `python harness/shared/x.py` or from `harness/<stack>/scripts/`, so a helper module would itself need the bootstrap it replaces; the only real dedupe is a CLI-contract change (`python -m harness.shared.x`) for every adopter Makefile and hook, which is a product decision, not hygiene. The per-stack scripts are additionally root-of-trust artefacts (DEC-004: listed in `harness/<stack>/.governance/policy.json`, digested into the policy bundle), so rewriting twenty of them to save three lines each churns every digest for no behaviour change. `check_dedup.py` already bounds each per-stack shim to the shim-budget line count, which is the guard that matters. Revisit when the 3.9 floor moves and the entrypoint contract is reconsidered together (DEC-028)
