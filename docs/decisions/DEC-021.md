# DEC-021: A coverage-regression check was implemented via `scheduled-drift.yml`'s nightly `main-drift` loop (`

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

A request to "improve hooks/loops" considered wiring a coverage-regression check into `.mango/hooks/pre_completion_checklist.sh` (the Stop hook) and rejected it: that hook is declared in `.mango/settings.json`, which DEC-003 already established Claude Code does not read -- `.claude/settings.json` mirrors only the live `SessionStart` hook, by a human decision recorded as "its own reviewed change, never a side effect." Wiring new logic into a dormant hook would look wired while doing nothing, the exact failure class this repository's own liveness tests exist to catch elsewhere. Implemented instead through an already-live channel: `coverage-python` joins `.github/workflows/scheduled-drift.yml`'s nightly `main-drift` loop (`digest-regen`, `check-dedup`, `validate`), open-an-issue-on-failure, never blocking a PR -- matching that workflow's own stated design principle (drift no single PR's CI can catch). Justified specifically because `main` has no branch ruleset yet (DEC-018's still-open highest-value item): per-PR CI is advisory, not required, so a PR that dropped coverage below the policy floor could merge unnoticed until this catches it on `main` itself. Purely Python; the job needed no new Node/pnpm setup
