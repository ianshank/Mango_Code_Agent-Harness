# DEC-015: GitHub Copilot's review of PR #35 found six real defects in the DEC-013/DEC-014 batch, all fixed her

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

GitHub Copilot's automated review of PR #35 (the DEC-013/DEC-014 tech-debt batch) found six real defects the batch's own local verification missed, all fixed in the same PR. `governance_json.read_json_object`'s `except OSError` did not catch `UnicodeDecodeError` -- a `ValueError` subclass raised by `Path.read_text()` before `json.loads()` ever runs -- so a badly-encoded policy file crashed uncaught instead of classifying as "malformed"; it now has its own except clause, matching check_dedup.py's pre-refactor behavior of treating a decode failure as corruption. `governance/broker.py`'s `_load_json` collapsed every failure into a plain `ValueError`, contradicting R-DH-5 ("each [caller] MUST keep raising its own existing exception type"): the pre-refactor function let `Path.read_text`/`json.loads` raise their natural `FileNotFoundError`/`OSError`/`JSONDecodeError`, and only the not-a-dict case was an explicit `ValueError`; `_load_json` now maps `read_json_object`'s `.error` back to those three type families explicitly, with new direct unit tests (`test_governance_broker.py::TestLoadJsonPreservesItsPreRefactorExceptionTypes`) since the only caller's broad `except Exception` had made the type distinction invisible at every existing test's altitude. `make pre-pr`'s prerequisite list never included `secrets`, contradicting README.md's claim that `pre-pr` runs both scanners; `secrets` joins its prerequisites (`ci`/`ci-python` deliberately still exclude it, unchanged, since interpreter-independent gates repeating per matrix leg is the exact anti-pattern that keeps `secrets` and `audit` as dedicated jobs in the first place). `pip-audit` was installed unpinned, in both the Makefile and CI, unlike gitleaks/osv-scanner; `PIP_AUDIT_VERSION` (2.10.1) now pins it in the root Makefile, matching `GITLEAKS_VERSION`/`OSV_VERSION`, and CI installs through `make audit-install-python` rather than an inline `pip install` that could drift from it. The `audit` job's `pip-audit` invocation resolved dependency markers and transitive constraints only under Python 3.11, even though the project supports and tests 3.9/3.10/3.12 -- a vulnerability specific to a dependency version selected only under another interpreter would never surface; `audit` splits into `audit-python` (interpreter-scoped scan) and `audit` (that plus the Node delegation, unchanged locally), and a new `audit-matrix` CI job runs `audit-python` across the same three interpreters as `build`, keeping the one-time Node delegation on the original `audit` job alone. `test_ci_gate_coverage.py`'s audit mapping proved only that some workflow contains a `make audit` command, not that nothing could guard it behind a conditional; a new `test_audit_gate_is_invoked_unconditionally` mirrors the existing secret-scan liveness check (no `if:` anywhere in the invoking job's block). Also fixed: GOVERNANCE_SKILL.md's DEC-013 summary said the two `__init__.py` files "are restored" and, later in the same paragraph, that adding them "was tried and reverted" -- a stale sentence left over from an earlier draft of the entry, contradicting both the authoritative decision-log.md text and the files' actual presence; removed
