# DEC-050: One slice of the 2026 standards-audit remediation (H16, M1, H6, H7, M25)

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

2026 standards audit H16 / M1 / H6 / H7 / M25, one slice of the remediation program. **H16:** `orchestrator.verification_timeout_sec` (900) bounds the harness's own verification run (`make test-python` via `VerificationRunner`) and `api_timeout_sec` (300) goes back to bounding one model round-trip. The suite takes 70-85 s on the 4-core container the model latency was tuned in; a runner four times slower hit the shared 300 s ceiling and a passing change was graded BLOCKED/harness_fault, because `TimeoutExpired` is BROKER_FAILED. 900 is roughly ten times the measured duration: room for a cold cache, a shared runner and a suite twice this size, while still bounding a hung subprocess (R-VP-5). The wiring R-CQ-14 landed deliberately is unwound here rather than quietly, and the new key is subject to DEC-043 -- a present policy that omits it stops the run. **M1:** `execute_loop` mints one `ToolBudget(max_tool_calls_per_task)` and threads it through planner, reasoner and verifier, which is what `tool_budget.py` was written for; each role had been given a fresh allowance, so the per-task value was enforced at three times its declared number. A task whose roles sum past the budget now stops in the role that crosses it. **H6:** `JSONFormatter` emits `extra=` fields as top-level keys, excluding the standard `LogRecord` attributes and any key `debug_dump.CREDENTIAL_NAME_PATTERN` grades as a credential name; `execute_loop` mints a `run_id` (uuid4 hex) exposed on the loop and the facade, and one structured event is logged per model call (agent, iteration, latency, token usage when the response reports it) and per tool call (tool, permitted, outcome, duration) -- DEBUG for routine, WARNING for denials, never the arguments or the messages. **H7:** `ToolDispatcher.dispatch` validates arguments against the tool's own `function.parameters` schema (required keys, `additionalProperties: false`, primitive types) before any handler runs, via the stdlib validator `tool_arg_validation.py`; a failure returns `Error: invalid_arguments: <key>` to the model and the executor is never reached. `jsonschema` is not added: the lock is hashed and protected and the subset is four keywords. A handled tool with no advertised schema is refused rather than run unchecked. `_slice_bounds_denial` keeps the range checks; the validator takes the type checks that used to reach it. **M25:** the eight gate scripts that called `logging.basicConfig` directly now call `json_logging.configure_gate_process_logging`, which installs the one gate handler on the root logger and, like `basicConfig`, defers to a process that configured logging first; `validate_specs.py` no longer hard-codes INFO and `validate_plan.py` no longer crashes on `--log-level BOGUS`. `mcp_server.py` keeps its own `basicConfig`: it is a stdio transport, not a gate, and its WARNING floor is part of that protocol's contract. Protected paths are touched by design and the PR carries the per-file attestation
