# DEC-060: Retire NS-17/NS-21 temporary rollback regression pins after origin re-lands the forward feature

## Context

On the Windows-portability integration branch, CI temporarily rolled back the
NS-17 (workspace-scoped agent memory / planner `{open_gaps}`) and NS-21
(post-turn hook observation) implementation files so inverted regression tests
(`test_ns17_rollback_regression.py`, `test_ns21_rollback_regression.py`) could
pass. Those tests asserted the *absence* of `resolve_memory_dir`, `_fifo_trim`,
`format_gaps_for_planner`, the `agent_memory` policy block, the `{open_gaps}`
planner slot, and `ToolDispatcher.policy_path`.

`origin/main` re-landed the forward implementation under DEC-057 (hypothesis
revision / memory store split) and DEC-058 (hypothesis surfacing), plus the
NS-17 retention/scoping and NS-21 post-turn recording that the rollback had
removed. Keeping the inverted pins would force the suite to fail against the
correct forward code — the opposite of a regression guard.

## Decision

Delete `harness/shared/tests/regression/test_ns17_rollback_regression.py` and
`harness/shared/tests/regression/test_ns21_rollback_regression.py`. The forward
contracts are pinned by origin's `test_hypothesis_revision.py`,
`test_hypothesis_surfacing.py`, `test_hypothesis_surfacing_regression.py`,
`test_meta_tools.py`, `test_orchestrator_agent_loop.py`, and the DEC-057/058
specs. These modules were never in `REQUIRED_REGRESSION_MODULES`, so the tier
pin does not block removal.

## Consequences

A future accidental rollback of the memory/hypothesis feature is caught by the
forward tests and specs, not by inverted "feature must be absent" pins. Any
new temporary rollback must land with its own DEC and must not revive these
filenames without superseding this entry.
