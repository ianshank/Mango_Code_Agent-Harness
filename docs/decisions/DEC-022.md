# DEC-022: Two second-round audit findings evaluated individually rather than mechanically fixed: `verification

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

A second-round tech-debt audit (same PR) found two items shaped like this log's recurring "unlinked literal duplicating a policy value" pattern (Pattern 1: COV_MIN=80; the size_budget_lines/check_dedup/check_py_compat trio; DEC-005; DEC-006; DEC-009; the langgraph GraphPolicy fail-open earlier in this same PR) and evaluated each on its own facts rather than mechanically re-applying the same fix. `harness/shared/governance/verification.py`'s `VerificationRunner.__init__(..., timeout: int = 300)` duplicates `orchestrator.api_timeout_sec`'s policy value, but this module's own docstring states a stronger, deliberate contract than the already-fixed `process_backend.py` case: "the broker, the command and the timeout are all injected. Nothing here reads the environment or the filesystem at import time." Sourcing the default from policy would violate that documented import-time-purity guarantee (`policy_loader.orchestrator_defaults()` reads `governance-policy.json`), and the one production call site (`mango_mas_orchestrator.py`) already injects the real policy value explicitly -- the literal is confirmed unreachable in production; only ~10 `test_verdict.py` constructions omit it, which is ordinary test terseness, not a drift risk. Left as-is; recorded so a future audit does not re-flag it without this reasoning. Separately, `harness/shared/langgraph/decorators.py`'s `@with_authority`/`@budgeted` were found fully implemented and unit-tested in isolation but never applied to any of the 10 real node functions in `nodes.py` (only synthetic dummy functions in their own tests) -- contradicting `NEXT_STEPS.md`'s checked-off claim that they were "enforced... at node boundaries," now corrected to unchecked with the accurate state. Both decorators also fail *open* on a lookup error, the opposite of every other governance control in this repository, moot only while unwired. Wiring them is deliberately deferred rather than attempted in this hygiene pass: doing so correctly means fixing the fail-open behavior in the same change (this pattern's own lesson), which is a behavioral change to live-shaped node code, not a default-sourcing fix, and belongs in its own spec and review
