# DEC-023: PR #55's unconditional `mcp>=1.0.0,<3.0` in `requirements.txt` broke CI two ways: Python 3.9 (no pub

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

PR #55 added `mcp>=1.0.0,<3.0` to `requirements.txt` unconditionally, breaking CI two ways: Python 3.9 (no published `mcp` release supports below 3.10) and mypy (`mcp_server.py` called `types.Tool(..., inputSchema=...)`, but the field is `input_schema`). Inspecting `mcp`'s actual released source across versions rather than guessing from one mypy error: the package restructured `mcp.types` around a separate `mcp_types` dependency at 2.0.0, and `inputSchema` is the *only* accepted spelling below that -- `Tool`'s 1.x model has no `input_schema` field or alias, and `model_config=ConfigDict(extra="allow")` means passing it silently drops as an unmatched extra field, failing validation on the still-missing required `inputSchema`. A prior, now-superseded PR review comment argued the opposite rename was needed, citing `mcp==1.0.0` specifically -- correct for that exact version, but not for what this range actually resolves. Fixed by tightening the floor to `mcp>=2.0.0,<3.0; python_version >= "3.10"` and renaming the call site, rather than the narrower fix of merely pinning to whatever CI happens to resolve today. A second option was considered and rejected for now: moving `mcp` into `[project.optional-dependencies]` alongside `langgraph`, which is the architecturally-consistent choice -- `mcp` has the identical "gate on installed, not on Python version" shape `langgraph`'s own module docstring documents -- but no CI job installs any extras group today, so doing the same to `mcp` would permanently remove mypy's ability to catch this exact class of bug on every leg, the same gap already silently accepted for `langgraph`. Left in `requirements.txt` so mypy keeps checking it; revisit if this repo ever wires an extras-group install into CI, at which point `mcp` and `langgraph` should move together, not just one. Also added `test_dependency_lockstep.py`: `requirements.txt` and `pyproject.toml`'s `[project.dependencies]` had no mechanical check that they declare the same packages, which is exactly how this PR's `mcp` addition landed in one file and not the other, missed across four rounds of human review
