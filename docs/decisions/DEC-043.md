# DEC-043: A _present_ policy that has lost a key fails closed in every Python reader, matching `policy.ts`

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

Every Python policy reader fails closed on a *present* policy that has lost a key, as `policy.ts:58-69` always has. The readers took `section.get(key, default)`, which cannot distinguish "this adopter has no policy file, so use the built-in" from "the policy governing this run no longer states this", and answered the literal for both. The first is a supported deployment; the second is a policy that no longer says what every reader believes it says, and the substituted value is always a *plausible* one, which is what makes the failure silent: deleting `orchestrator.max_iterations` returned 10 and the loop ran on; deleting `coverage.lines` returned 90 while the file a reviewer had been pointed at said nothing about coverage. `policy_loader` now resolves a block through `_Section`, which carries the data *and* whether a file backs it, so one call site expresses both outcomes and no accessor restates the rule; `coverage.optional_extras` keeps a distinct `.optional` accessor because "this deployment declares no extras" is a statement rather than a hole. `validate_invariants.load_protected_patterns` drops its `[".github/**"]` fallback — the worst instance, because one surviving pattern kept the run printing `[PASS] Protected Paths` while the enforcement layer, the agent control surface and the runtime gates were all unprotected — and `_policy_limit` drops its `limits` default. **Accepted behaviour change**: `MAX_FILE_LINES`, `MAX_TEST_FILE_LINES` and `MAX_SHIM_LINES` may now only *tighten* a budget (`min(env, policy)`), and an ignored loosening is logged rather than silent. They were previously returned verbatim, so anyone who could set an environment variable could switch a gate off while it still printed its PASS line — a gate whose report cannot be told apart from a real pass is worse than no gate, because it is trusted. `governance/verify_zero_skips.py` resolves `ID_RE` on first use rather than at import: `_decision_id_regex` raises `SystemExit` on a malformed policy, which is correct for a gate and fatal for an import, and at module scope any importer inherited that exit as its own crash with no call in the traceback to explain it. Six mutation proofs, one of which failed first: the import-purity test set `_POLICY_PATH` after importing, so it passed with the fix reverted — a module-scope read has no "after import", and the test now stages a copy of the module beside a malformed policy. Absence stays the adopter path throughout; every fail-closed test is paired with a control asserting the built-in defaults still apply when no policy file exists
