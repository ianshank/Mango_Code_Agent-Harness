# DEC-068: MIN_MESSAGES_BEFORE_FALLBACK is a ReAct transcript-shape constant, not a policy budget

## Context

`harness.shared.orchestrator.loop.ExecutionLoop._finalize_response` used a
bare `3` in `len(messages) > 3` before falling back to the last tool result.
`docs/specs/reflection-hardening-increment.md` R-RHI-5 requires that literal to
become a named constant triaged in `test_constant_triage.py`.

The value is the shape of a ReAct transcript (system, user, at least one
assistant/tool exchange), not an adopter-tunable budget. Putting it in
`governance-policy.json` would invite operators to "tune" a protocol floor
that, if lowered, would treat an incomplete first turn as a successful tool
fallback.

## Decision

`MIN_MESSAGES_BEFORE_FALLBACK = 3` in `harness.shared.orchestrator.loop` is a
true constant of the ReAct transcript shape. It is recorded here rather than
as a policy key. `test_constant_triage.py` carries the row; a present policy
is not asked for this key.

## Consequences

- The fallback still fires only after a real tool exchange, not on an empty
  first assistant message.
- Changing the floor requires a superseding decision, not a policy edit.
