# DEC-020: New gate-like modules land under `harness/shared/gates/` going forward

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

`harness/shared/`'s ~37 top-level files mix gate scripts (`check_*.py`, `validate_*.py`), tool plumbing (`tool_*.py`), and core orchestration with no subdirectory boundaries, unlike `governance/`/`langgraph/`, which are already split out. A full migration was considered and rejected for this pass: `protected_paths` has ~15 individual literal `harness/shared/{check,validate}_*.py` entries that would all need updating, `check_dedup.py`'s shim-classification logic enforces per-stack mirrors delegate to the exact current shared path, and the migration would add shim/indirection surface in the same audit that flagged reducing shim surface as a goal. Adopted instead: new gate-like modules land under `harness/shared/gates/` going forward; all 11 existing `check_*.py`/`validate_*.py` files stay exactly where they are. Zero shim churn, zero protected-path edits, zero `check_dedup.py` impact -- a convention for new code, not a migration of old code
