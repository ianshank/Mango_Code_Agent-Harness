# DEC-016: DEC-015's `PIP_AUDIT_VERSION` pin (2.10.1) broke the new `audit-matrix` job's 3.9 leg immediately: `

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

DEC-015's `PIP_AUDIT_VERSION` pin (2.10.1) broke the `audit-matrix` job's 3.9 leg on its first real CI run: `pip-audit` 2.10.0 raised its own floor to `Requires-Python >=3.10`, so `pip install pip-audit==2.10.1` has no installable candidate under 3.9 and `make audit-install-python` failed closed with a dependency-resolution error rather than silently degrading. `dependency-audit (3.10)` and `dependency-audit (3.12)` both passed clean on the same commit, confirming the matrix job itself works as designed -- this was a version-pin defect, not a design defect. Capped at 2.9.0, the newest release that still declares `Requires-Python >=3.9`, matching this project's own floor exactly. Discovered from the actual CI run this PR's own `audit-matrix` job added, immediately validating the job's purpose: a single-interpreter local check (this development environment runs Python 3.11) could not have caught a 3.9-specific installability failure
