# DEC-067: A developer tool is graded by its invocation form; an in-place formatter is not a gate run

## Context

`command_actions._BY_PROGRAM` maps a program name to one action. That is right for
`cat` and wrong for any tool that both inspects and rewrites. `ruff` and `eslint`
were each graded `test_execute` in every form.

`ruff format` and `ruff check --fix` rewrite every Python file they reach, in
place. `write_targets` looks for a redirect and finds none in such a command, so
the broker's write-policy loop was never given a path to refuse. The result was
a protected-path write door standing open behind an action every implementing
role holds.

Reproduced end to end against `50bed5f`, through the real `ExecutionBroker` as
`implementer`, with a workspace containing `harness/shared/governance/broker.py`:

```
direct write to that path denied? -> harness/shared/governance/broker.py matches a
  protected path; changing it requires a reviewed change with the infra-reviewed
  attestation, not an agent write
broker status: SUCCESS | action: test_execute
protected file rewritten by a test_execute command: True
```

The write policy refuses that exact path by name, and `ruff format .` rewrote it
anyway with a SUCCESS verdict. This is the same defect class as the `GNUmakefile`
and `python3 forge.py` routes the 2026 standards audit recorded under B4: an
effect the command string does not name.

The same table settles a second, opposite defect. `CLAUDE.md` mandates invoking
pinned tools through the interpreter (`python -m ruff`, `python -m mypy`) under
DEC-013. Both graded `UNCLASSIFIED_ACTION` — "python is not a modelled program" —
so the form the contributor guide requires could not execute through the broker,
while the bare form it forbids could. The guide and the classifier were not
merely unaligned; they were opposed.

## Decision

A tool whose action depends on the form it is invoked in is graded by that form,
in one declarative table (`harness/shared/governance/tool_forms.py`) that drives
both the bare and the `python -m` paths from a single entry point.

- An invocation that only inspects keeps the action its program already had, so
  this table only ever narrows. `ruff check .` stays `test_execute`.
- An invocation that rewrites files **and names them** is `write` over exactly
  those paths, which `write_targets` reports so the existing write policy refuses
  a protected one.
- An invocation that rewrites files over a directory, a glob, or no operand at
  all resolves to `UNCLASSIFIED_ACTION`. There is no enumerable target set to
  check, which is the same reason `python -c` is unmodelled: it can rewrite
  anything it finds.
- A flag carrying an action of its own outranks the form. `mypy --install-types`
  shells out to pip and is `external_write` whatever else it is asked to do.

`python -m pytest` and `python -m pip install` keep their existing shape rules in
`command_actions`. They are correct, pinned by tests, and model no mutating form,
so folding them in would be churn against a working gate.

## Consequences

- An agent can no longer reformat the tree through the broker. That is the
  intended loss: a recursive in-place rewrite of protected sources is not work an
  agent performs unreviewed. `make lint` is unaffected — `make` is graded against
  the canonical makefile and never decomposed — so the repository's own gates run
  exactly as before.
- `python -m ruff check` and `python -m mypy` now execute, so DEC-013 is followable
  for the first time.
- `ruff format a.py` remains available and is checked against the write policy
  per named file, so the ordinary bounded case is not lost.
- The table is the extension point. A tool added to `_BY_PROGRAM` that can rewrite
  in place must declare its mutating forms here, or it reopens this door.

Pinned by `harness/shared/tests/test_tool_forms.py`, including the end-to-end
reproduction above as a regression and a mutation case: reverting the wiring in
`_classify_program` turns 13 of its 25 tests red.
