# DEC-046: The thirteen open Dependabot pull requests are dispositioned, and R-CQ-2's premise for five was wron

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

R-CQ-2 / AC-2: the thirteen open Dependabot pull requests are dispositioned here, and the plan's premise for five of them was wrong. R-CQ-2 predicted "#62-#66 superseded by the SHA pins of R-CQ-9". They are not superseded. Within minutes of PR #82 merging, Dependabot rebased all five onto the new pins and now proposes majors *in the pinned form*: #64 offers `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`, which is the exact commit `git ls-remote --tags https://github.com/actions/checkout` reports for `refs/tags/v7.0.1`, with the version comment preserved -- and the same holds for #62 (setup-go v7.0.0), #63 (setup-node v7.0.0), #65 (pnpm/action-setup v6.0.10) and #66 (setup-python v7.0.0). That is a better outcome than the plan expected and a different one: it proves the pin form survives Dependabot's own rewrite as a one-line diff, and it leaves five accurate major-bump proposals rather than five stale ones. DEC-045 deferred those majors deliberately, and `.github/dependabot.yml` keeps the `github-actions` ecosystem enabled precisely to "keep the majors moving", so these five stay open as the tracked queue for that deferred decision; closing them as superseded would record a reason that is false and Dependabot would reopen them weekly regardless. #67 (mypy 1.11.2 -> 2.3.1) is closed as blocked on NS-6, and the block was measured rather than assumed: installing mypy 2.3.1 shows `Requires-Python >=3.10`, and `mypy --python-version 3.9` answers `error: argument --python-version: Python 3.9 is not supported (must be 3.10 or higher)` -- the mypy 2.0 `--python-version 3.9` removal, confirmed against the release itself. `make ci-python` runs `lint-python`, and therefore mypy, on every matrix leg including 3.9, and `[tool.mypy]` sets no `python_version`, so mypy targets whichever interpreter runs it. That is two independent blocks on one leg: the package has no installable candidate under 3.9 at all -- the DEC-016 pip-audit failure repeated exactly -- and no target setting on a newer runner can typecheck *for* 3.9 either. No configuration retires this; the floor has to move first (NS-6). #68 (pytest-socket), #70 (pydantic-core), #71 (pytest) and #73 (langgraph-checkpoint-postgres) are closed as orphans of DEC-033: removing the `pip` ecosystem from `.github/dependabot.yml` on 2026-09-03 stopped new PRs but did not close the ones already open, so four of them outlived the decision that retired them. Against `requirements-lock.txt` a per-package pin is a no-op or a reintroduction of the pinning the lock supersedes, and `lock-upgrade-check` is the Python upgrade signal; #73 additionally proposes the Postgres checkpointer, which the lock excludes on purpose because nothing under `harness/` imports it. #69 (tsx), #77 (knip) and #78 (typescript-eslint) stay open: they are `npm`, an ecosystem `dependabot.yml` deliberately keeps enabled, and closing a bot PR that the configuration is designed to produce would contradict the configuration rather than tidy it. Net: five closed, eight open with a recorded reason each -- not the twelve closures R-CQ-2 assumed
