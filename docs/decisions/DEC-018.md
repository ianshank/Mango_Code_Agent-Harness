# DEC-018: `NEXT_STEPS.md`'s required-status-check list (for the still-unapplied branch ruleset) was accurate w

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

`NEXT_STEPS.md`'s branch-ruleset paragraph listed 5 required status checks (`build (3.9)`, `build (3.10)`, `build (3.12)`, `build-full`, `secret-scan`) as "taken from a real run" -- true when written, but the list was never updated after DEC-013/DEC-016/DEC-017 added the `audit`/`audit-matrix` jobs, which report as `dependency-audit` and `dependency-audit (3.9/3.10/3.12)`. A ruleset configured from the stale list today would leave the entire dependency-audit gate (including the two CVE-bearing legs DEC-017 documents) permanently unrequired, with a green-looking ruleset masking it. Found while peer-reviewing an external analysis of this repository that flagged `main` having no branch ruleset as the highest-priority gap; verified directly against `.github/workflows/python-package.yml` rather than against the doc's own prior claim. The list is corrected to the 9 names GitHub actually reports, and `test_ci_gate_coverage.py` (`TestRequiredStatusChecksListIsAccurate`) now parses both the workflow file and the doc's list and fails closed on any divergence -- proved by temporarily renaming a job (doc-omits-check case) and by temporarily dropping a name from the doc (doc-lists-stale-check case), both confirmed to fail before being reverted. Applying the ruleset itself is a repository-settings change outside this PR's diff; this closes the mechanical drift that made the last three attempts at documenting the list wrong within days of being written
