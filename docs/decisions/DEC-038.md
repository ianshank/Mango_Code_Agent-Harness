# DEC-038: The protected-path attestation table is derived and verified, not transcribed

## Context

Recorded as a governance decision on the historical pipe log.

## Decision

The protected-path attestation table required by `harness/CONTRACT.md` is derived and verified in CI instead of transcribed by hand. `check_protected_paths` fails a PR touching a protected path unless `ALLOW_GITHUB_CHANGES=1`, which the workflow derives from the `infra-reviewed` label, and the contract requires the PR description to carry a per-file table so the reviewer applying that label knows what they are attesting to. Nothing derived that table: it was copied out of a CI log, and on PR #76 -- this repository's own governance PR, whose subject is gates that pass on absent evidence -- a comment claimed the table had grown to thirteen rows when the validator's set at that head was ten, verified by replaying `is_protected` over `git diff origin/main...339cd6d`. A table a reviewer trusts, overstating what it covers, is the DEC-024 failure class reproduced inside the control written to prevent it, and it is the more dangerous direction: an inflated count reads as thoroughness. `harness/shared/governance/attestation.py` imports `is_protected`, `git_modified_files` and `load_protected_patterns` from `validate_invariants` rather than reimplementing them, so the printed table and the enforced set cannot diverge -- asserted as symbol identity, not as agreement on today's tree, because `git_modified_files` acquired its `core.quotePath=false` handling exactly the way a second implementation would have missed. `--check` compares a written description against that set and fails closed three ways: no attestation section, a section with no table, or any row-to-path mismatch in either direction (a row naming a path the change does not touch invites the reviewer to attest to something absent, which is the same overstatement pointed the other way). Table parsing is scoped to the section under a heading matching `--section` (default: any heading naming an attestation) because a PR description legitimately carries other tables; a header row is identified by the separator beneath it rather than by position, so a table introduced by a paragraph parses correctly. The base branch is never a literal -- explicit flag, then `GITHUB_BASE_REF`, then the remote's published `origin/HEAD` -- so an adopter fork whose default branch is not `main` needs no edit. Wired as `make attestation` / `make attestation-check` and as a `build-full` step that runs on every pull request and is deliberately *not* gated on the label, since the reviewer must be able to read a verified table before deciding; the description reaches the script through a file written from an environment variable, never interpolated into a shell command. The module lives under `harness/shared/governance/` so the existing `harness/shared/governance/**` pattern protects it: a gate that anything unreviewed can weaken is the defect this branch exists to close, and that placement costs it one row in its own table
