# DEC-064: The Python floor moves to 3.10, retiring the 3.9 carve-outs DEC-017 and DEC-028 recorded

## Context

`docs/specs/reflection-hardening-increment.md` (Step 1/2, R-RHI-1, superseding
DEC-028's own precondition — "a product decision that needs its own spec")
re-measured the Python 3.9 floor against `33f21044` and found it nine months
past EOL (2025-10-31), forcing two forked dependency pins (`pytest`,
`pytest-randomly`), a `python_version >= "3.10"` marker on `mcp` and
`langgraph` that every remaining interpreter now satisfies unconditionally,
`mypy` frozen at 1.11.2 (2.x requires Python >=3.10 to even install — DEC-046
confirmed this by installing it and running `mypy --python-version 3.9`), and
a required CI check (`dependency-audit (3.9)`) that could never fail because
DEC-017 had marked it `continue-on-error` for an unpatchable-under-3.9 CVE
set.

## Decision

`pyproject.toml`'s `requires-python` is `>=3.10`. Every 3.9-specific
carve-out is deleted rather than re-homed, per `reflection-hardening-increment.md`'s
C-RHI-1: the `build` and `audit-matrix` CI matrices drop the `"3.9"` leg and
add `"3.14"`; `audit-matrix`'s `continue-on-error` (DEC-017) is removed
entirely, since every fix DEC-017 named requires Python >=3.10, which every
remaining leg now satisfies; the workflow's
`MANGO_CI_DESELECT_LANGGRAPH: ${{ matrix.python-version == '3.9' && '1' || '' }}`
binding is removed (no remaining leg lacks `langgraph`) — the general
"optional extra not installed" deselection mechanism itself
(`coverage.optional_extras`, `_session_hooks.py`) is untouched, since it is a
reusable adopter-fork feature, not a 3.9-specific one; `pytest==8.4.2` and
`pytest-randomly==3.16.0`'s `python_version < "3.10"` pins are removed,
leaving the single `>=3.10`-floor release of each; the `python_version >=
"3.10"` markers on `mcp` (`requirements.txt`, `pyproject.toml`) and
`langgraph`/`langgraph-checkpoint-postgres` (`requirements-langgraph.txt`,
`pyproject.toml`) are removed as now-permanent tautologies; `ruff`'s
`target-version = "py39"` is removed so it derives from `requires-python`
instead of a second, independently-driftable literal; `mypy` moves to 2.3.1
with `warn_unused_ignores = true` newly enabled. `harness/shared/check_py_compat.py`
is **not** modified: its `PEP604_MIN = (3, 10)` check derives the effective
floor from the CI workflow matrix at runtime (`resolve_min_version`), so it
self-disables the PEP 604 check the moment the matrix's lowest version reaches
3.10 — this is why the gate was built to read the matrix rather than hard-code
a version, and no code change was needed for it to keep protecting the new
floor from PEP 604 constructs going forward. `requirements-lock.txt` is
regenerated with `uv pip compile --universal --generate-hashes --python-version
3.10 -o requirements-lock.txt requirements-dev.txt requirements-langgraph.txt`.
`.github/rulesets/main.json`'s required-check list drops
`dependency-audit (3.9)` and gains `dependency-audit (3.14)`;
`harness/shared/tests/_workflow_paths.UNSUPPORTED_LEG` and its two consuming
tests (`test_workflow_contracts.py`'s unsupported-leg-deselects test,
`test_dependency_lock_contracts.py`'s langgraph-marker-exclusion test) are
removed, since no leg is unsupported any more.

**DEC-028 is superseded** by this decision: both of its 3.9 consequences (the
`coverage.optional_extras` waiver's 3.9 trigger, and the forked `pytest` pin)
end exactly as DEC-028 itself said they would — "the day the floor moves to
3.10." The general `coverage.optional_extras` mechanism DEC-028 introduced is
not retired; only its 3.9-specific activation is.

**DEC-017 is not superseded** — it remains an accurate historical record of
the CVEs `audit-matrix`'s first real run found and why the 3.9 leg was marked
`continue-on-error` at the time — but its `continue-on-error` carve-out no
longer exists in the workflow this decision edits; a required check that
cannot fail on its own finding is not a check (R-SR-23), and every fix DEC-017
named is installable and clean on every leg the matrix now carries.

## Consequences

- Python 3.9 is no longer supported. This is the one breaking change in the
  increment and is intentional: 3.9 has been EOL for nine months.
- `mypy` gains a year of fixes and `warn_unused_ignores` enforcement it could
  not run under before.
- Two forked dependency pins collapse to one each; `mcp` and `langgraph`
  install unconditionally instead of behind a marker every supported
  interpreter already satisfies.
- One required CI check (`dependency-audit (3.9)`) that could never
  meaningfully fail is removed from the branch ruleset; `dependency-audit
  (3.14)` (fully enforced, no `continue-on-error`) replaces it.
- `check_py_compat.py` required no code change — the gate that reads the
  matrix rather than hard-coding a version proved out exactly as designed.
